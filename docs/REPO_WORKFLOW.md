# Соответствие GitHub и локальных клонов

> Дата: 2026-11-06.
> Статус: действующая политика; пункт про роли ветвей ждёт решения о консолидации.

## 1. Диагноз: почему клоны разошлись

В октябре 2026 история репозитория была переписана фильтром, который заменил
реальные хосты, адреса и имена аккаунтов на плейсхолдеры (`example.com`,
`203.0.113.x`, `user02`). Перезапись истории меняет SHA **всех** коммитов, включая
корневой, поэтому у старого локального клона и GitHub формально нет общего предка:

```
$ git merge-base master origin/master      # пусто
$ git status -sb
## master...origin/master [ahead 105, behind 109]
```

`ahead/behind` в такой ситуации бессмысленны: это не «несколько коммитов туда-сюда»,
а две несвязанные линии. Обычные `git pull`, `git merge` и `git rebase` тут не
работают и только создают мусор.

Дополнительно в локальном клоне накопилось ~470 неотслеживаемых файлов (отладочные
скрипты `server/check_*.py`, заметки, `microbin-ru`, `tmp/`), которые мешают видеть
реальную картину в `git status`.

## 2. Принятая модель

1. **GitHub — единственный источник истины и единственная линия истории.**
   Любой клон можно удалить и склонировать заново без потери кода.
2. **Локальный клон — зеркало GitHub.** Расхождение допустимо только в
   неотслеживаемых файлах: `.env`, `local/`, заметки, отладочные скрипты.
3. **Опубликованную историю не переписываем никогда.** Санитайз — это проверка
   перед коммитом, а не `filter-repo` по уже опубликованным ветвям.
4. **Реальные значения не попадают в отслеживаемые файлы.** В репозитории живут
   только плейсхолдеры; реальные хосты, IP и имена — в `local/sanitise-blacklist.txt`
   и в серверных `/etc/nyxpanel/*.env`.

Почему так: переписывание истории ломает все клоны сразу, делает невозможными PR и
merge, обнуляет `git blame` и превращает каждую синхронизацию в ручную операцию.
Проверка перед коммитом стоит секунды и не ломает ничего.

## 3. Роли ветвей

| Ветка | Содержимое | Состояние |
|---|---|---|
| `main` | линия 1.14: `panel/`, `server/`, `ops/`, один установщик | активная разработка |
| `master` | линия 1.12: `bin/`, `panel/`, текущий прод | default на GitHub, стабильная |
| `feat/*` | тематические ветки от `main` | по мере работы |
| `archive/*` | старые линии и layout'ы | только чтение |

`main` и `master` разошлись в точке `b5c3b34` (1.12). В `main` 48 коммитов, включая
смену layout'а; в `master` — 5 коммитов, в основном документация и санитайз.
Консолидация линий — отдельное решение, см. §8.

## 4. Плейсхолдеры

| Что | Плейсхолдер |
|---|---|
| Домен | `example.com`, `panel.example.com`, `vpn.example.com` |
| IPv4 | `203.0.113.0/24`, `198.51.100.0/24`, `192.0.2.0/24` (TEST-NET) |
| Имя аккаунта | `user01`, `user02`, `admin` |
| Публичный IP сервера | `203.0.113.20` |
| Почта | `admin@example.com` |

Реальные значения хранятся только локально, в неотслеживаемом
`local/sanitise-blacklist.txt` (каталог `local/` в `.gitignore`), по одному
литералу на строку. Файл не коммитится и не покидает машину.

## 5. Проверка перед коммитом

```bash
python ops/check_no_secrets.py
```

Скрипт читает чёрный список из `local/sanitise-blacklist.txt` (или из пути в
`NYX_SECRETS_LIST`), проходит по всем отслеживаемым файлам и печатает
`path:line: pattern #N` при совпадении. Коды выхода: `0` — чисто или списка нет,
`1` — найдены совпадения, `2` — ошибка запуска.

Хук (по желанию, локально):

```bash
cat > .git/hooks/pre-commit <<'EOF'
#!/bin/sh
exec python ops/check_no_secrets.py
EOF
chmod +x .git/hooks/pre-commit
```

Хук не заменяет ревью: он ловит случайные вставки, а не осмысленные решения.

## 6. Как публиковать изменения

**Основной путь (предпочтительно):**

1. `git fetch origin`
2. `git switch -c feat/<тема> origin/main`
3. Правки с плейсхолдерами, `python ops/check_no_secrets.py`
4. `git push -u origin feat/<тема>`, затем PR в `main`
5. После merge ветку удалить

**Переходный путь, если в рабочей копии реальные значения:**

1. Закоммитить изменения в локальную ветку (она не публикуется).
2. Снять патч: `git format-patch origin/main..HEAD -o /tmp/nyx-patches`
3. В чистом клоне от `origin/main` применить патч и заменить реальные значения
   плейсхолдерами по карте из `local/sanitise-map.txt`.
4. `python ops/check_no_secrets.py`, затем push и PR.

Чего делать нельзя: `git filter-repo`, `git rebase --root`, `push --force` по
опубликованным ветвям. Это снова сделает клоны несвязанными.

## 7. Если реальные значения уже попали в историю

Приватность репозитория не делает утечку безопасной: значения остаются в объектах,
форках и бэкапах. Порядок действий:

1. Считать засвеченное скомпрометированным и **ротировать**: пароли панели, ключи
   REALITY, ключи AmneziaWG, токены ботов, пароли пользователей.
2. Переписать историю можно только как разовую согласованную операцию: после неё
   все клоны переклонируются, старые не мержатся.
3. Зафиксировать дату, ветки и список ротированных секретов в `docs/STATUS.md`.

## 8. Открытые решения

1. **Default branch.** Сейчас на GitHub default — `master` (1.12, прод). Логично
   перевести default на `main` (1.14) и оставить `master` как стабильную линию
   до перевода прода, либо наоборот — влить 1.12-документацию в `main` и
   заархивировать `master`.
2. **Консолидация.** Пока две линии живут параллельно, любой фикс нужно применять
   дважды. Это главный источник будущих расхождений.
3. **Неотслеживаемые файлы.** ~470 файлов в локальном клоне стоит разобрать:
   нужное — в `docs/`/`ops/` через PR, отладочное — в архив, остальное удалить.

## 9. Чеклист при расхождении

```bash
git fetch --prune origin
git status -sb
git merge-base --is-ancestor origin/main HEAD && echo "можно merge" || echo "НЕЛЬЗЯ merge"
```

- Если общего предка нет — не мержить. Склонировать заново или сбросить ветку на
  `origin/*` после бэкапа.
- Если есть — обычный rebase/merge, как в любом репозитории.
- Перед push — `python ops/check_no_secrets.py`.

## 10. Состояние локального клона после выравнивания (2026-11-06)

- `master` = `origin/master`, `main` = `origin/main`, upstream выставлены.
- Старые линии сохранены локально: `legacy/real-1.12` (реальные значения, 1.12) и
  `legacy/main-pre-1.14` (старый layout).
- Локальная работа, которая была в рабочей копии, сохранена в
  `local/wip-tproxy-1.12`.
- Полный бэкап (bundle всех refs + 469 файлов рабочей копии) лежит вне репозитория:
  `%TEMP%\opencode\nyxpanel-backup-20261106-040401`.
- Неотслеживаемые файлы оставлены на месте: они не мешают git, но требуют разбора.
